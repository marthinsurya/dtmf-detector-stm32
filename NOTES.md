# GLOSSARY
DTMF -  Dual-Tone Multi-Frequency
Q15 - fixed-point format: int16 where the value is x / 32768, range [-1, 1)
Goertzel - recursion that gives the energy of one frequency bin in N samples (cheaper than a full FFT for 8 tones)

# Step 2 Notes (C, Q15)
Q15 hit-rate accuracy 200/200/199/161/60/30/20 vs float 200/200/200/176/79/42/23 at SNR 0 to -30 dB (200 keys)
Float is more accurate as expected. Likely due to Q15 quantization at low SNR. 

1. **Overflow.** The Goertzel state grows ±2e6 (22 bits), so it is kept in int32 and the energy in int64. Cast to int64 before multiply.
2. **Rounding.** `(int16_t)x` truncates & adds a small bias on conversion, so `float_to_q15` uses `roundf` instead.
3. **Input scaling.** Test signal peaks at ~2.2, outside the Q15 range [-1, 1). `INPUT_SCALE` 0.25 keeps it in range. Effect on accuracy to be investigated in step 3.
4. **Coefficients.** Coefficients generated by `tools/gen_coeffs.c`, so remove `cosf` calculation on hardware.


# Step 3 Notes (Float v Q15)
Cycle counts for float vs Q15 on the STM32F407, 800 samples, 8 tones.

1. **Coeff shift.** Coeff cos(ω) are stored in Q15 and the recurrence needs 2·cos(ω), so the product is shifted by 14 instead of 15.
2. **Result at -O0** Q15 costs about 2x float (595721 vs 292228 cycles) for 1 key test. Q15 has worse result: FPU does float in hardware, while Q15 needs int64_t on a 32-bit core.
3. **Result at -O2** Q15 costs about the same as float (87839 vs 86711 cycles) for 1 key test. Gap disappears, likely because the recurrence is latency-bound. `-O2` is 3.4x faster for float and 6.8x for Q15.
